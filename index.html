Contech-GPT 건설 인허가·건설기준 규제 판단 RAG 시스템

“이 부지에 이 건물을 지으려면 어떤 법령·조례·기준이 적용되는가”에 근거를 붙여 답하는 사내 서비스. 문서 검색형 챗봇을 넘어 법령 API를 1순위 진실 소스로 두고 답변을 검증하는 구조.

문제

  • LLM이 존재하지 않는 법령명·조문을 만들어내는 환각이 규제 도메인에서는 치명적
  • 질의는 일상어(“다세대 주차장 몇 대”), 문서는 법률어(“부설주차장 설치기준”) — 검색 격차
  • 법령·조례·KDS·해석례·지자체 조례 등 근거 소스가 7종 이상으로 분산

설계

  • Cascade Prefetch — LLM 호출 전 RAG·법령API·GraphDB·KDS·웹·해석례를 Stage1 병렬 선수집 → 교차 발견된 참조를 Stage2 2차 수집 → 단일 LLM 스트리밍
  • Golden Card 81장 — 규제 판단 카드를 정형화해 CardRepository에 등록, 질의 슬롯(지역·용도·규모) 매칭 시 답변 최상단에 주입. 5-Layer 검증(형식·근거·카드별 pytest·smoke·품질셋 재채점)
  • 환각 방어 후처리 체인 — LawLinkInjector(원문 링크) → LawNameGuard(GraphDB 대조로 미확인 법령명 검출) → CompletenessAuditor(리스크 프로필 대비 누락 토픽 감사) → grounded 후속 선택지
  • 질문 유형 7단계 라우팅 — 첨부 분석·범위 밖·교정·코드·최신정보·법령 도구·기본 Cascade. fast-path는 검색·LLM 생략으로 비용 절감
  • RAG 2-lane + 소프트 플로어 — 원본 질의 lane과 LLM 재작성 lane 병합, 타입별 버킷 상위 N건은 점수 무관 보존해 저점수 도메인(KDS) 컨텍스트 소실 방지
  • LLM Gateway 단일 진입점 — reasoning-class(gpt-5.x)와 chat-class 파라미터 차이를 어댑터가 흡수, retry·backoff·JSON 추출 표준화
  • 지명 해소(PNU·토지이용규제) → 지자체 조례 실시간 조회, 멀티 서비스 대화 기록 DB, Streamlit 관리자 패널(채팅 로그·검토 큐)

운영·품질

  • 1,000문항 QA셋(단일·복합 질문) 구축 + 5-Level smoke 자동 테스트(AutoTest)로 릴리스마다 회귀 검증, 실채팅 로그 분석 보고서로 라우팅 오류·미답변 유형 추적
  • 서버 이전(07월) — 사내망 → Tailscale 망으로 전 서비스 재바인딩, post_boot_check.sh(부팅 후 컨테이너·헬스 선언적 점검) 등 호스트 복구 절차 문서화·스크립트화
  • 외부 서비스 연동(09월) — 레거시 체크리스트 서비스의 질의를 full prefetch 경로로 라우팅하는 답변 API 추가, 스트리밍 중 법령 인용 번호·시행일 정합성(citation reconciliation) 핫픽스
  • 208 커밋, feat/fix/hotfix/savepoint 브랜치 + ci/* 브랜치로 CI 부트 가능성·네트워크 테스트 분리 관리. src2 실험 트랙은 A/B 실행 로그로 비교

LAON_AI LangGraph 네이티브 에이전트 재구현

Contech-GPT의 Cascade 로직을 LangGraph 완전 종속으로 다시 설계. 기존 코드를 import하지 않고 데이터 소스만 재사용해, 절차형 파이프라인을 상태 그래프로 옮겼습니다.

핵심 결정

  • 에이전트가 처음부터 도구를 고르는 경로를 그래프에서 제거 — cascade → grade_evidence → coverage_gate로 “무엇이 없는지” 확정한 뒤에만 gap_plan → gap_fetch 보완. 자율 tool-calling의 비결정성을 구조로 억제
  • Send 팬아웃으로 Stage1/2·Gap-fill 병렬 수집, reducer로 병합 · Command(goto) 라우팅 · interrupt()로 관할 미확정 시 추측 대신 되묻기
  • context_schema DI로 노드를 순수 함수로 유지 · BaseStore 장기 메모리로 체크리스트 Seed를 코드 배포 없이 추가 · RetryPolicy/CachePolicy 노드 단위 선언
  • validate 노드가 “근거는 있으나 답변이 샘” / “근거 부족”을 구분해 각각 synthesize / gap_plan으로 재진입
  • A/B/C 3개 변형 구현 후 자체 agent_eval로 비교 → 1개 선정, 릴리스 디렉토리 기반 배포
